# Architecture Council visual system

This document defines the public visual language for Architecture Council documentation and repository presentation.

## Design goal

The visual system should make the project feel like a deliberate decision product rather than an internal slide deck or autogenerated diagram set.

The core visual metaphor is an isometric decision chamber:

- a central Decision Core represents the decision under review;
- six surrounding nodes represent independent professional lenses;
- the Independent Chairman is visually elevated because the role synthesizes but does not vote;
- connecting lines represent evidence and challenge paths rather than hierarchy;
- depth, glass, glow, and geometric surfaces create a consistent 3D language without relying on raster screenshots.

## Vector source and PNG publication rule

Public documentation illustrations keep SVG as the canonical editable source, while GitHub-facing README and Skill landing-page presentation uses deterministic PNG derivatives.

The source/publication split provides:

- reviewable vector source and accessible SVG metadata;
- predictable GitHub rendering without direct SVG publication;
- lossless deterministic PNG generation at governed dimensions;
- SVG/PNG parity checks in CI;
- HiDPI publication dimensions without stretching;
- no fake vector wrappers for native raster assets.

PNG derivatives are committed only when they are part of the reviewed documentation contract. The repository does not use an ongoing privileged image commit-back workflow.

## Text inside illustrations

Illustrations are not substitutes for documentation.

- Keep body copy in Markdown.
- Use only short labels inside SVGs.
- Avoid paragraphs, wrapped sentences, and dense explanatory text inside graphics.
- Prefer labels such as `STRATEGY`, `WEIGHTED VERDICT`, or `KILL CRITERIA`.
- Keep important explanatory meaning available in adjacent Markdown and alt text.

## Color system

| Token | Value | Use |
|---|---|---|
| Deep background | `#07111F` | Primary canvas |
| Secondary background | `#111A36` | Depth and gradient endpoint |
| Cyan | `#65E6FF` | Decision core, information paths, technology |
| Violet | `#8A7CFF` | Weighted decision and technical depth |
| Emerald | `#54E0B4` | Delivery and confirmed outcomes |
| Amber | `#F7C873` | Chairman, governance, reversal signal |
| Pink | `#FF7AB6` | Operations, unknowns, kill criteria |
| Primary text | `#EAFBFF` | High-contrast labels |
| Secondary text | `#9FB4CB` | Supporting copy |

## Geometry

- Use isometric prisms and cubes for decision stages and reviewer nodes.
- Use a raised gold prism for the Independent Chairman.
- Use rings and dotted paths to show deliberation and evidence flow.
- Keep perspective and light direction consistent within one illustration.
- Avoid decorative complexity that makes the information model harder to read.

## Accessibility

Every SVG must include:

- `role="img"`;
- an `aria-labelledby` relationship;
- a concise `<title>`;
- a useful `<desc>`;
- meaningful alt text at the Markdown or HTML embedding point.

Do not encode essential instructions only in color. The adjacent text must explain the model independently of the image.

## Social preview

`skills/architecture-council/assets/social-preview.svg` is the canonical source for the GitHub social preview. The committed `social-preview.png` is the governed 1280 x 640 publication derivative used for raster upload. GitHub repository settings remain a separate configuration surface.

## Validation

Repository validation must fail when:

- a required SVG is missing or malformed;
- an asset has no usable `viewBox`;
- a public SVG includes scripts or external image dependencies;
- the Skill landing page is missing;
- the required human-facing Skill README sections drift;
- the README references a missing local image.
